Three products, three real operating environments.

Features below are drawn from each product’s public repository. Check the repository and product for the current release and deployment requirements.

OrderRestro — restaurant operations

Open-source, self-hosted restaurant POS and management software designed for dine-in, takeaway, delivery, and kitchen work. Its documented core stack is PostgreSQL, a NestJS API, and a Next.js web app, deployed together with Docker Compose.

  • Billing and POS for restaurant orders, discounts, payments, refunds, and configured tax workflows
  • Table and reservation management, floor plans, waitlists, QR table ordering, and table transfers
  • Kitchen display, KOTs, multi-station routing, and prep tracking
  • Menu categories, modifiers, combos, scheduled availability, and seasonal menus
  • Ingredients, recipe costing, suppliers, purchase orders, goods received, waste, and batch/lot records
  • CRM, loyalty, memberships, gift vouchers, feedback, and visit history
  • Staff roles, attendance, shifts, leave, payroll, and tip-pool workflows
  • Accounting, expenses, cash close, statements, budgets, and tax summaries
  • Delivery zones, fees, minimums, ETA, driver assignment, and status flow
  • Branch switching, stock transfers, dashboards, reports, exports, and scheduled report emails
  • Marketing campaigns over configured email, SMS, or WhatsApp providers, with opt-out
  • UPI QR, thermal printing, local LAN operation, CasaOS/ZimaOS deployment, and a thin Windows client

Project status: The repository labels some areas as planned or in progress; consult its current roadmap before assuming every listed workflow is complete. Repository and roadmap · Product · Project story.

KinetiRx — pharmacy and small-clinic workflows

Self-hosted pharmacy and small-clinic management built with Go/Gin, React, PostgreSQL, and Docker Compose. The core system does not require an AI API key.

  • Dashboard for sales, dues, drawer cash, stock valuation, expenses, and inventory turnover
  • GST point-of-sale billing with strip/loose dispensing, discounts, mixed payment modes, and receipt printing
  • Live sync between counters, medicine and test inventory, batch/expiry tracking, rack and distributor details, and low-stock alerts
  • Due-khata ledger, payment history, and WhatsApp reminders
  • Medicine order list and purchase-order sharing by distributor
  • Purchase-bill OCR with optional Gemini integration; human review remains important
  • OPD scheduling, follow-up reminders, patient visit and purchase history, and blood-test tracking
  • Expenses, business-development tasks, role-based staff accounts, invoice settings, and cash-drawer reconciliation
  • Administrative reset tooling with a rolling backup; server-side JWT and role/permission checks
  • Optional clinical assistant and optional MCP integration for compatible assistants
  • Docker, CasaOS/ZimaOS, and offline fallback mode when AI is not configured

NodeDR POS — retail checkout and inventory

Open-source, offline-first retail point-of-sale software for small shops. Its documented stack uses a web app with a local machine or an operator-selected VPS deployment.

  • Barcode scanner and camera-based barcode/QR scanning; generate and print labels for items without a code
  • GST billing, checkout, receipt printing/PDF, and reprinting of past invoices
  • Inventory, CSV/Excel import, suppliers, customer records, dues, and reorder suggestions
  • UPI QR setup, configurable payment methods, and optional weighted items and serial/IMEI tracking
  • Online-order workflow with supported store integrations and a custom-store API
  • Team accounts and role-based access
  • Docker Compose, CasaOS/ZimaOS, and a Windows Store client
  • Local-network access for shop devices; optional remote/VPS operation with added dependencies
  • Updater workflow designed to replace app containers without touching the data volume

Repository and documentation · Product · Project story.

Important boundary

Offline-first describes certain core workflows. It does not mean cyberattacks cannot happen, that power and hardware never fail, that every payment rail works offline, or that backups are automatic. Each deployment needs its own access controls, updates, tested backups, and recovery plan.
